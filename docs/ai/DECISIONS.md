# Architectural Decisions

## Формат записей

- **Решение** — что выбрано.
- **Контекст** — почему.
- **Статус** — Active | Superseded (если заменено, указать ссылку/дату и новое решение).

---

## ADR-1: Память проекта в docs/ai/

**Решение**: Единственный источник истины по проекту — файлы в `docs/ai/`. История чата памятью не считается.

**Контекст**: Стабильный контекст между сессиями, версионирование через git, отсутствие зависимости от логов и рассуждений в чате.

**Статус**: Active.

---

## ADR-2: Один backend-сервис

**Решение**: Вся бизнес-логика интеграции с AI и управления доступом — в одном Spring Boot приложении.

**Контекст**: Упрощение деплоя и разработки на текущем масштабе; при росте можно выносить домены в отдельные сервисы и фиксировать в DECISIONS.

**Статус**: Active.

---

## ADR-3: Google и xAI через OpenAI-совместимый клиент

**Решение**: Провайдеры `google` (Gemini) и `xai` (Grok) маршрутизируются через существующий `OpenAiClient`, т.к. оба поддерживают OpenAI-совместимый API (`/chat/completions`, Bearer auth).

**Контекст**: Минимально инвазивно — не нужно создавать новые клиентские классы. API URL в записи neural_networks указывает на OpenAI-совместимый эндпоинт провайдера. Если в будущем потребуется специфичная логика (native API features), можно создать выделенный клиент и обновить фабрику.

**Статус**: Active.

## ADR-4: Social posting как отдельный клиентский API

**Решение**: Публикация постов в Telegram, Facebook и X вынесена в отдельный endpoint `POST /api/social/posts` под `X-API-Key`, без регистрации этих платформ как `neural_networks`. Контракт поста расширяется через `attachments[]`, чтобы клиент отправлял один запрос со всем текстом и файлами, а backend выбирал платформенный способ публикации.

**Контекст**: Это не AI-провайдеры и не требуют выбора сети/лимитов нейросетей. Секреты платформ по текущему контракту передаёт клиент в запросе; сервис использует их только для транзитного вызова и логирует результат без значений секретов. Для Telegram backend сам выбирает `sendMessage`/`sendPhoto`/`sendVideo`/`sendDocument`/`sendMediaGroup`; содержимое файлов в `request_logs` не сохраняется.

**Статус**: Active.
